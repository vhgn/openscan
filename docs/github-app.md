# Creating the GitHub App credentials

openscan signs people in and reads their code through a **GitHub App**. For a local run you create your own app once (about 5 minutes), paste five values into `.dev.vars`, and `npm run setup` checks them with GitHub.

Don't want to create one yet? `npm run setup -- --demo` signs you in as a demo user that reviews public repositories, no GitHub App needed.

## 1. Create the app

Open **https://github.com/settings/apps/new** (or, for an organization, *Organization settings → Developer settings → GitHub Apps → New GitHub App*) and fill in:

| Setting | Local value | Why |
| --- | --- | --- |
| GitHub App name | anything unique, e.g. `openscan-dev-<you>` | Becomes the app's URL slug |
| Homepage URL | `http://localhost:3000` | Required by GitHub |
| Callback URL | `http://localhost:3000/api/auth/github/callback` | "Sign in with GitHub" returns here. The browser follows it, so `localhost` works |
| Expire user authorization tokens | ✅ on | openscan refreshes them |
| Request user authorization (OAuth) during installation | ⬜ off | The Setup URL handles the return from an install |
| Setup URL | `http://localhost:3000/api/github/setup`, with ✅ *Redirect on update* | GitHub sends you back here after installing or changing repositories |
| Webhook → Active | ⬜ off for a plain local run | GitHub can't reach `localhost`. See [Webhooks](#4-optional-webhooks) to turn them on |
| Repository permissions → **Contents** | Read-only | Reads the code |
| Repository permissions → **Metadata** | Read-only (set automatically) | Lists repositories |
| Repository permissions → **Code scanning alerts** | Read-only (optional) | Imports CodeQL/Semgrep alerts into reviews |
| Subscribe to events | **Push** (only when webhooks are on) | Starts a review on every push |
| Where can this GitHub App be installed? | *Only on this account* is enough locally; *Any account* for a shared deployment | |

Click **Create GitHub App**.

## 2. Collect the values

On the app's settings page (*General*):

| `.dev.vars` key | Where to find it |
| --- | --- |
| `GITHUB_APP_ID` | **App ID**, near the top (a number) |
| `GITHUB_CLIENT_ID` | **Client ID** (starts with `Iv`) |
| `GITHUB_CLIENT_SECRET` | **Client secrets → Generate a new client secret**. Copy it right away; GitHub shows it once |
| `GITHUB_APP_PRIVATE_KEY` | **Private keys → Generate a private key**. A `.pem` file downloads; paste its whole contents |
| `GITHUB_APP_SLUG` | The last part of the app's public URL, `https://github.com/apps/<slug>`. `npm run setup` fills it in for you |

`GITHUB_WEBHOOK_SECRET`, `SESSION_SECRET` and `LWC_SECRET` are generated by `npm run setup`; you don't need to invent them.

## 3. Put them in `.dev.vars`

`npm run setup` creates `.dev.vars` on its first run. Fill in:

```
GITHUB_APP_ID=1234567
GITHUB_CLIENT_ID=Iv23li…
GITHUB_CLIENT_SECRET=…
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
MIIEow…
-----END RSA PRIVATE KEY-----"
```

The private key can be pasted as a quoted multi-line value (as above) or on one line with literal `\n` between lines. The PKCS#1 key GitHub gives you works as-is.

Then run:

```bash
npm run setup
```

It signs a JWT with your key, asks GitHub which app it belongs to, checks the client ID matches, and sets `GITHUB_APP_SLUG`. When it prints **Ready**, start the app with `npm run dev`, open http://localhost:3000 and click **Connect GitHub**. `.dev.vars` is git-ignored; never commit it.

## 4. Optional: webhooks

Without webhooks everything works except reviews on push and live updates when you change the app's repository access on GitHub (the Setup URL redirect and the **refresh** link on the repositories step cover that). To get webhooks locally:

1. Expose your machine: `npx cloudflared tunnel --url http://localhost:3000` (no account needed) and note the `https://….trycloudflare.com` URL.
2. In the app settings, turn **Webhook → Active** on, set **Webhook URL** to `<tunnel URL>/api/github/webhook`, set **Webhook secret** to the `GITHUB_WEBHOOK_SECRET` from `.dev.vars`, and subscribe to **Push**.
3. If you also want to open the app through the tunnel, set `APP_URL=<tunnel URL>` in `.dev.vars` and change the app's Callback and Setup URLs to the tunnel too.

## Troubleshooting

| `npm run setup` says | Fix |
| --- | --- |
| `GITHUB_… is missing` | The value is empty or still the placeholder from `.dev.vars.example` |
| `GitHub rejected GITHUB_APP_ID + GITHUB_APP_PRIVATE_KEY (HTTP 401)` | The key belongs to a different app, was revoked, or the App ID is wrong. Generate a new private key |
| `GITHUB_CLIENT_ID is … but the app's client ID is …` | Copy the Client ID again from the same app |
| `Couldn't reach GitHub to verify the app` | Offline or behind a proxy; the check is skipped. `--offline` skips it on purpose |

Signing in fails with *redirect_uri is not associated with this application*: the Callback URL must be exactly `APP_URL/api/auth/github/callback` (`APP_URL` defaults to `http://localhost:3000`).

For production, the same values are stored as Worker secrets; see "Deploy to Cloudflare" in [TECHNICAL.md](./TECHNICAL.md).
